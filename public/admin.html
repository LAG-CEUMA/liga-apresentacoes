Owners veem tudo e liberam. Monitores têm acesso de aluno e só veem a mais o que você marcar para cada um. Alunos veem as aulas de nível membros e públicas. Cada mudança vira um commit no liga-curriculo, com seu nome; pode levar até 1 minuto para valer para todos.

1. Nível de cada aula

Para tornar uma aula pública, clique em Público na linha dela. Só owners (padrão): só vocês veem. Membros: alunos e monitores logados. Público: qualquer pessoa com o link, sem login. O roteiro nunca depende desse nível: só owners e monitores com permissão.

Como tudo se encaixa (visão geral)
  1. Onde ficam os arquivos: as aulas (slides e roteiros), as tarefas de casa e a lista de acessos ficam no repositório privado LAG-CEUMA/liga-curriculo no GitHub. Ninguém de fora enxerga esse repositório.
  2. Onde as pessoas assistem: este site (lag-ceuma.vercel.app) lê o repositório e mostra a aula só para quem tem permissão. O site não guarda cópia: se você mudar um arquivo no GitHub, o site passa a mostrar a versão nova em até 1 minuto.
  3. Quem é quem: o site identifica a pessoa pelo login do GitHub (só o nome de usuário; nenhuma permissão sobre a conta dela é pedida).
  4. Onde ficam as regras: no arquivo acesso/acesso.json do liga-curriculo. Este painel é só uma forma fácil de editá-lo.
Os 4 tipos de pessoa
  • Owner: vê tudo (slides, roteiros, tarefas de casa), muda níveis e permissões. Dê só a quem coordena a liga.
  • Monitor: começa igual a um aluno. Só vê a mais o que um owner marcar para ele (slides de uma aula, roteiro de uma aula).
  • Aluno: usuário na lista de alunos. Vê aulas de nível Membros e Público. Nunca vê roteiros.
  • Visitante: qualquer pessoa sem login ou fora das listas. Vê só aulas de nível Público.
1. Nível de cada aula: o que cada botão faz
  • Só owners (padrão para toda aula nova): só owners abrem. Use enquanto a aula está em preparo.
  • Membros: owners, monitores e alunos da lista, depois de entrar com o GitHub.
  • Público: qualquer pessoa com o link, sem login. Use para as aulas que a liga quer divulgar.

O que acontece no repositório: o clique grava um commit em acesso/acesso.json com seu nome (ex.: "Portal: afonsofarias definiu nivel-00-tutorial/aula-02 como publico"). O arquivo da aula em si não muda.

Para desfazer: clique no nível anterior. Quem já abriu uma aula pública pode ter uma cópia em cache por alguns minutos; para retirar algo realmente sensível, deixe em "Só owners" e avise.

O roteiro (guia do apresentador) nunca é público nem de membros, não importa o nível dos slides.

2. Monitores e permissões
  • Adicionar monitor: digite o usuário do GitHub (sem @) e clique em adicionar. Ele entra sem nenhuma permissão extra, ou seja, vê o mesmo que um aluno.
  • Caixas de seleção: cada caixa libera uma aula (slides) ou um roteiro para aquele monitor. Salva ao marcar; não existe botão "salvar".
  • Remover: tira o monitor da lista e apaga as permissões dele. Ele continua podendo ver o que é público.

Repositório: cada alteração é um commit em acesso/acesso.json.

3. Listas de owners e alunos
  • Um usuário do GitHub por linha, sem @, sem espaços. Maiúsculas e minúsculas não importam.
  • Salvar listas substitui as duas listas inteiras pelo que está nas caixas. Confira antes de salvar: se apagar uma linha, a pessoa perde o acesso.
  • Owners fixos (linha cinza abaixo das caixas) vêm da variável ADMIN_USERS na Vercel: não saem desta tela, nem por engano. É a "chave-mestra" para ninguém se trancar fora.
  • Para ser owner, a pessoa precisa de conta no GitHub. Não precisa ser membro da organização para entrar no site.
Tarefas de casa (/semanas)
  • Mostra, por semana, o texto da aula e a tarefa que o aluno receberá. Fica em liberacao/nivel-XX/semana-NN/ (aula.md e tarefa.md) no liga-curriculo.
  • Sugerir alteração abre o arquivo no GitHub: edite, escreva uma mensagem curta e clique em Commit changes. A página mostra a versão nova em cerca de 1 minuto.
  • Nada é enviado aos alunos por esta página. O envio é feito depois, pelo script ferramentas/liberar-semana.py (primeiro em simulação; só envia de verdade com --executar). Nessa hora a tarefa.md vira uma Issue no repositório de cada aluno.
Quanto tempo leva para valer? E se algo der errado?
  • As mudanças feitas aqui valem em até 1 minuto (o site guarda uma cópia curta para ser rápido).
  • Se der erro ao salvar (mensagem vermelha), recarregue a página e tente de novo. Se duas pessoas salvarem ao mesmo tempo, o site tenta de novo sozinho.
  • Todo histórico fica no GitHub: em liga-curriculo → acesso/acesso.json → History você vê quem mudou o quê e quando, e pode voltar a uma versão anterior.
  • O login dura 7 dias. Se der "Só owners" estando logado, saia e entre de novo.
Dicas de segurança para owners
  • Não coloque como owner quem só precisa ver aulas: use Aluno ou Monitor.
  • Antes de tornar uma aula pública, abra-a em aba anônima e confira se não há nada interno (nomes, contatos, links privados).
  • Para trocar quem é "owner fixo", é preciso editar ADMIN_USERS na Vercel (Settings → Environment Variables) e fazer redeploy.
